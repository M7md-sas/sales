# دليل المطوّر

مكتوب لمن يفتح المشروع لأول مرة ويحتاج يعدّل أو يضيف شيئاً.
الكود وتعليقاته بالإنجليزي؛ هذا الملف بالعربي.

---

## القاعدة الوحيدة التي لا تُكسر

> **تطبيق العامل لا يسترجع أي شيء. أبداً.**

هذه ليست قاعدة واجهة، بل بنية المشروع كله. لو وجدت نفسك تكتب في
`app/js/worker/` أو `app/js/data/submit.js` أي شيء يقرأ من قاعدة البيانات —
فالتعديل خاطئ، مهما بدا مبرَّراً.

الآلية ثلاث طبقات، كل واحدة تكفي وحدها:

1. **قاعدة البيانات:** لا توجد سياسة RLS للعامل على `daily_entries` إطلاقاً،
   فأي استعلام يرجع `[]` حتى لو صيغ يدوياً خارج التطبيق.
2. **الدالة الوحيدة:** `submit_photo()` ترجع `{ ok, code }` فقط. حتى إعادة
   الإرسال على يوم موجود ترد بنفس الرد تماماً — لئلا يستنتج أن صفاً كان موجوداً.
3. **الكود:** `app/js/data/submit.js` فيه دالة واحدة، وملفات العامل لا
   تستورد أياً من وحدات القراءة أصلاً.

ولهذا أيضاً لا يُخزَّن على هاتف العامل شيء بعد نجاح الإرسال — ولا حتى وقت
آخر إرسال. الطابع الزمني رقمٌ متنكّر: يخبره أي الأيام وصلت، ومنها يستنتج
أيها لم يصل.

## أين يجلس كل شيء

```
app/js/
├── config.js        الملف الوحيد الذي يتغيّر بين بيئة وأخرى
├── core/            لا يعرف شيئاً عن الشاشات
│   ├── supabase.js    العميل. لا يستورده أحد خارج data/
│   ├── auth.js        دخول، جلسة، حارس الدور
│   ├── strings.js     كل نص عربي في التطبيقين (المرفق B)
│   ├── format.js      أرقام لاتينية، تواريخ الرياض، عملة
│   ├── dom.js         el/$/delegate/busy — بدون إطار عمل
│   └── errors.js      رمز الخادم ← رسالة عربية
├── data/            الطبقة الوحيدة التي تكلّم Supabase
├── worker/          التقاط + ضغط + طابور
├── owner/           موجّه + شاشة لكل ملف تحت views/
└── ui/              مكوّنات مشتركة بين التطبيقين
```

القاعدة: **الشاشة لا تستدعي Supabase.** تطلب من `data/` وتعرض ما يرجع.
لو احتجت استعلاماً جديداً، مكانه `data/`، لا داخل الشاشة.

## كيف تضيف شاشة للمالك

ثلاث خطوات، ولا شيء رابع:

**١.** أنشئ `app/js/owner/views/اسمها.js`:

```js
import { el } from '../../core/dom.js';
import { T } from '../../core/strings.js';

export const title = T.myScreen;   // العنوان في الشريط العلوي
export const showBack = true;      // زر الرجوع

// ctx = { settings, refreshBadge }
export async function render(root, params, ctx) {
  root.innerHTML = '';
  root.append(el('div', { class: 'card' }, [
    el('h2', { text: 'مرحبا' }),
  ]));

  // اختياري: أعِد دالة تنظيف تُستدعى عند مغادرة الشاشة
  return () => { /* أوقف المؤقتات، ألغِ الرفع، حرّر عناوين blob */ };
}
```

**٢.** أضفها إلى `ROUTES` في `app/js/owner/main.js`:

```js
const ROUTES = [
  ...
  ['/اسمها', myView, 'more'],   // الثالث = التبويب الذي يُضاء
];
```

**٣.** أضف نصوصها إلى `core/strings.js`. لا تكتب عربياً داخل الشاشة مباشرة —
النصوص كلها في مكان واحد ليسهل تغييرها مع العميل.

للمسارات ذات معامل: `['/day/:date', dayView, 'archive']` ثم `params.date`.

## أشياء تكرّرت وستحتاجها

**`el()` يقبل الشكلين:**

```js
el('div', { class: 'card' }, [child])   // بخصائص
el('tbody', [row, row])                 // بدونها
```
لو مرّرت الأبناء في خانة الخصائص فسيتعرّف عليها. (هذا الخطأ حصل فعلاً أثناء
البناء، وكان صامتاً تماماً: `setAttribute` يحوّل العنصر إلى نص بدل أن يفشل،
فتظهر الشاشة فارغة بلا أي رسالة — ولذلك صار `el()` يتسامح معه.)

**الأرقام:** استخدم `money()` أو `amount()` أو `count()` من `core/format.js`،
وضع `class="num"` على أي رقم في HTML. هذا ما يمنع ظهور الأرقام هندية (٢٦٠)
ويمنع انقلاب الرقم حول «ر.س» في اتجاه RTL.

**لا تجمع المبالغ في جافاسكربت.** عمود `total` محسوب في قاعدة البيانات.
الجمع في المتصفح يعطي فروق هللات (المرفق C). الاستثناء الوحيد هو المجموع
المعروض مباشرة أثناء التعديل في بطاقة المراجعة، وهو عرض لا تخزين.

**التواريخ:** `todayRiyadh()` دائماً، لا `new Date()`. اليوم التجاري بتوقيت
الرياض وينتهي منتصف الليل، وساعة الهاتف غير موثوقة. الخادم يتحقق مجدداً.

**استدعاءات الخادم:** لفّها بـ `attempt()` من `core/errors.js` — توحّد
الأشكال الثلاثة (خطأ مرمي، مغلّف `{ error }`، ورد `{ ok, code }`).

## الأنماط

`css/tokens.css` هو مصدر المظهر. غيّر متغيّراً هناك فيتبعه التطبيقان.
**لا تكتب لوناً أو مقاساً في أي ملف آخر.**

- `--accent` واحد، `--ink` واحد، والباقي درجات.
- الأخضر والكهرماني والأحمر **محجوزة للحالة فقط** — لا للزينة. الكهرماني
  يعني «القراءة غير مؤكدة» والأحمر يعني «فشلت»، وهذا ما يعتمد عليه المالك
  ليقرر أين ينتبه.
- الترتيب: `tokens` ← `base` ← `components` ← `worker/owner`.

## طابور عدم الاتصال

- التخزين: `localStorage` تحت `pending_photos`، بحد أقصى 3 صور.
- عند نجاح الإرسال يُحذف المفتاح كاملاً — لا يبقى حتى `[]`.
- الطرد التلقائي: إن ردّ الخادم `locked` أو `bad_date` تُحذف الصورة بدل
  إعادة المحاولة للأبد، وإلا بقي شريط «لم يتم الإرسال» ظاهراً بلا حل بيد العامل.
- التاريخ يُثبَّت **لحظة التصوير** لا لحظة الإرسال. ولهذا يقبل الخادم آخر ٧
  أيام (القاعدة ٢): صورة صُوّرت الخميس وأُرسلت السبت تحتفظ بتاريخ الخميس.

## Service Worker

شبكة أولاً، والكاش احتياطي فقط، ولا يلمس Supabase إطلاقاً (كل ما هو
cross-origin يمرّ دون تخزين).

اخترنا شبكة أولاً عمداً رغم أنه أبطأ قليلاً: الكاش أولاً يعني أن أي تصليح
تنشره لا يصل الهواتف حتى يرفع أحدهم `CACHE` في `sw.js`، وحين يُنسى يكون
العَرَض تطبيقاً يشتغل بكود الشهر الماضي بلا خطأ في أي مكان يفسّره.

عند التطوير محلياً: ألغِ تسجيل الـ SW وامسح الكاش، وإلا رأيت كوداً قديماً.

## التشغيل بلا Supabase

`start-demo.bat` — يشغّل الخادم الوهمي وخادم الملفات ويفتح المتصفح.
ادخل بأي كلمة مرور.

يدوياً:

```bash
python tools/mock_supabase.py                    # منفذ 5174
python -m http.server 5173 --directory app       # نافذة ثانية
```
ثم افتح `http://localhost:5173/?demo`

**لا تعدّل `config.js`.** العلامة `?demo` تحوّل الوجهة إلى الخادم الوهمي
وتُحفظ في `sessionStorage` فتنتقل معك بين تطبيق العامل ولوحة المالك. وهي
مقيّدة بـ `localhost` و `127.0.0.1`، فلا يمكن تفعيلها على نسخة منشورة
مهما كتب أحد في الرابط.

يولّد ٩٠ يوماً من التاريخ وثلاثة أيام بانتظار المراجعة تغطي الحالات الثلاث.
يفهم من PostgREST ما تستخدمه `data/` فقط: `eq/gte/lte/in`، `order`، `limit`،
العدّ الدقيق، والدوال الخمس.

**لا يطبّق أي حماية.** لا تختبر عليه أمناً، ولا تنشر بناءً موجّهاً إليه.

## قبل أن تدفع أي تعديل

1. `record_extraction` يجب ألا تظهر إلا داخل `supabase/functions/`.
   ابحث عنها في المشروع كله وتأكد.
2. `service_role` و `GEMINI_API_KEY` يجب ألا يظهرا في أي ملف تحت `app/`.
3. لو لمست العامل: أعد اختبارات الأمان الخمسة في
   [الإعداد-خطوة-بخطوة.md](الإعداد-خطوة-بخطوة.md) الخطوة ٩.
4. لو لمست المخطط: حدّث [DEVIATIONS.md](DEVIATIONS.md).
