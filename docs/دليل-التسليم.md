# دليل التسليم — من الألف إلى الياء

هذا الدليل لك أنت (المطوّر) وأنت تسلّم المشروع للعميل. يمشي بالترتيب من
قبل أول لقاء إلى ما بعد التسليم. التفاصيل التقنية لكل خطوة موجودة في
[الإعداد-خطوة-بخطوة.md](الإعداد-خطوة-بخطوة.md)، وهذا الدليل يحيل لها بالرقم.

**القاعدة الذهبية:** كل حساب يُنشأ **باسم العميل وبريده**، ولا شيء باسمك.
أنت تنفّذ الإعداد، لكن الملكية له من أول دقيقة. ولما تخلص تطلع أنت، والنظام
يكمل بدونك.

| المرحلة | المدة التقريبية | مع العميل؟ |
|---|---|---|
| ١. التجهيز | ساعة | لا |
| ٢. لقاء الموافقات | ٣٠ دقيقة | نعم |
| ٣. إنشاء الحسابات | ٣٠ دقيقة | نعم (يحتاج جواله للتفعيل) |
| ٤. الإعداد التقني | ساعة ونص | لا (بعد ما تاخذ الدخول) |
| ٥. النشر على GitHub Pages | ٢٠ دقيقة | لا |
| ٦. تجهيز الجوالات | ٢٠ دقيقة | نعم + العامل |
| ٧. اختبار القبول | ساعة | جزء منه معه |
| ٨. التدريب | ٣٠ دقيقة | نعم + العامل |
| ٩. التسليم والخروج | ١٥ دقيقة | نعم |

## ٢. لقاء الموافقات (مع العميل)

هذي قرارات تخصه هو، ولازم تكون **مكتوبة وموقّعة**، مو كلام شفهي. انسخ هذا
النموذج واطبعه:

```
قرارات العميل — تطبيق مبيعات المحل                   التاريخ: ____/____/______

١) التعديلات على المستند المعتمد (v4.0)
   اطّلعت على ملف DEVIATIONS.md (البنود ١–٢٦)، وأوافق على تطبيقها.
   ☐ أوافق على الكل     ☐ أوافق ما عدا البنود: ______________

٢) اليوم التجاري: يقفل الساعة ١٢ بالليل (٢٤ ساعة).          ☐ موافق

٣) الدخول: كلمة مرور ٨ خانات أو أكثر، فيها حرف ورقم ورمز.     ☐ موافق

٤) قراءة الصور عبر Gemini من جوجل:
   ☐ الباقة المجانية — أعرف أن جوجل قد تستخدم صور الدفتر لتحسين خدماتها.
   ☐ الباقة المدفوعة — تكلفة بسيطة شهرياً، وجوجل لا تستخدم الصور.

٥) الهدف الشهري للمبيعات: ____________ ر.س

٦) الأرشيف القديم: عدد صفحات الدفاتر القديمة تقريباً: ________
   ☐ أبي إدخالها     ☐ لا

٧) كلمات المرور يحفظها: ______________ (اسم الشخص)

التوقيع: ______________
```

**كيف تشرح البند ١ بدقيقة:** «المستند اللي اعتمدته كان ممتاز في التصميم،
بس فيه أخطاء برمجية، أخطرها يخلي العامل يقدر يغيّر الأرقام. صلّحتها كلها
وكل تصليح مكتوب في هذا الملف. التصليحات ما تغيّر طريقة استخدامك للتطبيق.»
اعرض عليه أبرز ثلاثة: البند ٤ (العامل يكتب أرقام)، والبند ١٠ (العامل يزوّر
القراءة)، والبند ١٩ (التطبيق ما يفتح بدون نت).

## ٣. إنشاء الحسابات (مع العميل)

كل الحسابات **ببريد العميل**. لو ما عنده بريد للمحل، أنشئ له Gmail جديد
خاص بالمحل. هذا أفضل من بريده الشخصي، لأنه يقدر يسلّمه لغيره مستقبلاً.

| # | الخدمة | الرابط | ملاحظة |
|---|---|---|---|
| 1 | بريد المحل (Gmail) | gmail.com | الأساس لكل اللي تحت |
| 2 | Supabase | supabase.com | سجّل بالبريد. **لا بطاقة** |
| 3 | Google AI Studio | aistudio.google.com | بنفس Gmail. **لا بطاقة** (إلا لو اختار المدفوعة) |
| 4 | GitHub | github.com | اسم المستخدم يصير جزء من الرابط، مثل `dukkan-sales` |

- [ ] فعّل **التحقق بخطوتين** على Gmail و GitHub و Supabase **بجوال العميل**.
- [ ] كلمات المرور تنكتب في ورقة الحسابات (القسم ٩) وتبقى **عنده**.
- [ ] عشان تشتغل أنت بعدين بدون كلمات مروره:
  - **Supabase:** Organization → Team → Invite بإيميلك كـ Developer.
  - **GitHub:** بعد إنشاء المستودع (القسم ٥) → Settings → Collaborators → أضفك.
  - مفتاح Gemini: يولّده هو ويعطيك إياه، أو ولّده بحضوره.

> **ليش كذا؟** لأنك بعد التسليم تقدر تشيل نفسك بضغطة، وما يحتاج تغيير أي
> كلمة مرور. وإذا سجّلت دخولك بحسابه هو، صارت عندك أسراره وما تقدر تثبت إنك
> نسيتها.

## ٤. الإعداد التقني (عندك)

امشِ على [الإعداد-خطوة-بخطوة.md](الإعداد-خطوة-بخطوة.md) **بالترتيب**:

- [ ] **الخطوة ١** — مشروع Supabase (المنطقة: Frankfurt)
- [ ] **الخطوة ٢** — شغّل `supabase/schema.sql`
- [ ] **الخطوة ٣** — الحسابان (`owner@shop.local` و `worker@shop.local`).
      اخترهما مع العميل، أو ضع مؤقتتين يغيّرها هو من الإعدادات بعد التسليم.
- [ ] **الخطوة ٤** — قفل التسجيل + الحد الأدنى ٨ + تقليل حد المحاولات
- [ ] **الخطوة ٥** — مفتاح Gemini، وسجّل الحد اليومي في `DAILY_CAP`
- [ ] **الخطوة ٦** — نشر الدالتين + الأسرار الثلاثة (`GEMINI_API_KEY`،
      `WEBHOOK_SECRET`، و`GEMINI_MODEL` اختياري)
- [ ] **الخطوة ٧** — الـ Webhook مع ترويسة `x-webhook-secret`
- [ ] **الخطوة ٨** — عبّئ `app/js/config.js`:

```js
SUPABASE_URL: DEMO ? 'http://localhost:5174' : 'https://<معرّف-المشروع>.supabase.co',
SUPABASE_ANON_KEY: DEMO ? 'demo-anon-key' : '<مفتاح anon public>',
```

- [ ] **الخطوة ٩** — `verify.sql` كله ✅ (ولا تكمل وفيه ❌ واحد)

## ٥. النشر على GitHub Pages

### ٥.١ المستودع

1. GitHub (بحساب العميل) → **New repository**.
2. الاسم: مثلاً `sales`. يصير رابط العامل:
   `https://<اسم-المستخدم>.github.io/sales/`
3. **Public.** GitHub Pages المجاني ما يشتغل إلا على المستودعات العامة.
   وهذا آمن هنا: ما فيه أي سر في الكود، ومفتاح `anon` عام أصلاً، والحماية
   كلها في قاعدة البيانات.
4. لا تضف README ولا .gitignore من GitHub (موجودة عندنا).

### ٥.٢ الرفع

من مجلد المشروع (اللي فيه `README.md`). ملف `.gitignore` يستبعد تلقائياً
`_internal/` (المستند الأصلي) و `.claude/`.

```bash
git init -b main
```

```bash
git add .
```

```bash
git commit -m "مبيعات المحل v4.2"
```

```bash
git remote add origin https://github.com/<اسم-المستخدم>/sales.git
```

```bash
git push -u origin main
```

**قبل الـ push** تأكد إن ما فيه أسرار في الملفات المرفوعة:

```bash
git grep -n -i "service_role\|AIza\|WEBHOOK_SECRET="
```

لازم ما يطلع إلا تعليقات وأسماء متغيرات، **بدون أي قيمة حقيقية**.

### ٥.٣ تفعيل الصفحات

1. المستودع → **Settings → Pages**.
2. **Source: GitHub Actions** (مو "Deploy from a branch").
3. تبويب **Actions** → انتظر `deploy-app` يصير ✅ (دقيقة أو دقيقتين).
4. الروابط:
   - العامل: `https://<اسم-المستخدم>.github.io/sales/`
   - المالك: `https://<اسم-المستخدم>.github.io/sales/owner/`

### ٥.٤ النبضة (لا تنساها)

- [ ] تشتغل لحالها مع أول رفع. بس شوف: Actions ← `keep-supabase-awake` ← ✅ (الخطوة ١٣ من دليل الإعداد).

### التحديثات بعدين

أي تعديل تسويه في `app/` ثم `git push` ينشر تلقائياً خلال دقيقتين. الجوالات
تاخذ النسخة الجديدة أول ما تفتح التطبيق وهي متصلة. و GitHub يخزّن الملفات
١٠ دقائق، فلو ما ظهر التعديل انتظر شوي.

## ٦. تجهيز الجوالات (مع العميل والعامل)

### جوال العامل (غالباً أندرويد)

1. افتح رابط العامل في **Chrome** (مو داخل واتساب، فتّحه في المتصفح).
2. القائمة ⋮ → **تثبيت التطبيق** / **إضافة إلى الشاشة الرئيسية**.
3. افتحه من الأيقونة **المبيعات** → اكتب كلمة مرور العامل → دخول.
4. اضغط **صوّر الدفتر** → يطلب إذن الكاميرا → **سماح**.
5. صوّر صفحة تجربة وأرسلها → لازم تطلع **تم الإرسال**.

### جوال المالك

- **آيفون:** افتح رابط المالك في **Safari** → زر المشاركة ⬆ → **إضافة إلى
  الشاشة الرئيسية**. آيفون ما يعرض التثبيت لحاله.
- **أندرويد:** مثل العامل، بس برابط `/owner/`.
- ادخل بكلمة مرور المالك.

> ⚠️ **لا تسجّل دخول المالك على جوال العامل**، ولا حتى للتجربة.

## ٧. اختبار القبول

- [ ] [اختبار-القبول.md](اختبار-القبول.md) **كاملاً** على الجوالين الحقيقيين.
- [ ] `tools/security-check.js` بحساب العامل ثم بحساب المالك (الخطوة ١٠ من
      دليل الإعداد) — كله ✅.
- [ ] الصفحة الحقيقية من الدفتر: الأرقام المقروءة قريبة من الصحيح؟
  - **نعم:** ممتاز.
  - **لا، والخطأ متكرر:** جرّب `GEMINI_MODEL=gemini-3.8-flash` (أدق، بس
    حده اليومي المجاني أقل). سر جديد بدون إعادة نشر، وبعدها «أعد القراءة».
- [ ] جرّب وضع الطيران على جوال العامل: التطبيق يفتح، يصوّر، والصورة تنرسل
      لما يرجع النت.
- [ ] امسح بيانات التجربة قبل التسليم (SQL Editor):

```sql
-- يمسح أيام التجربة فقط — غيّر التاريخ لأول يوم تشغيل حقيقي
delete from public.daily_entries where entry_date < '2026-10-10';
delete from public.audit_log     where entry_date < '2026-10-10';
```

وصور التجربة: Storage → `receipts` → حدّدها → Delete.

### الأرشيف القديم (لو العميل يبيه)

- لوحة المالك → المزيد → **استيراد دفاتر قديمة**.
- الحد اليومي المجاني (`DAILY_CAP`) يعني مئات الصفحات تاخذ كم يوم. يقدر
  المالك يكملها بنفسه بعد التسليم، والاستيراد يوقف عند الحد ويقول له «كمّل
  بكرة».

## ٨. التدريب (١٥ دقيقة لكل واحد)

**العامل** — اعطه [دليل-العامل.md](دليل-العامل.md) مطبوع، وعلّقه عند الصندوق:
1. كل يوم **قبل ١٢ بالليل**: افتح ← صوّر ← تأكد ← أرسل ← انتظر **تم الإرسال**.
2. لو ما فيه نت: لا تعيد التصوير، افتح التطبيق مرة ثانية لما يرجع النت.
3. لو طلع شريط أحمر: بلّغ صاحب المحل بالتاريخ.
4. لا تضغط «تسجيل الخروج».

**المالك** — امشِ معه على [دليل-المالك.md](دليل-المالك.md) على جواله هو:
1. المراجعة اليومية: افتح ← قارن مع الصورة ← اعتماد.
2. معنى الألوان (أخضر/كهرماني/أحمر)، وزر **أعد القراءة**.
3. «هذا اليوم بتاريخ غلط؟» للصفحة اللي انرسلت بعد ١٢.
4. تغيير كلمة مرور العامل (لو تغيّر العامل).
5. **التصدير الشهري** (Excel) — هذا نسخته الاحتياطية الوحيدة.
6. لو شاف «ما قدرنا نحمّل البيانات»: يتأكد من النت، ولو استمر يتصل فيك.

## ٩. التسليم والخروج

### ورقة الحسابات (تُسلَّم ورقياً، وتبقى عند العميل)

```
حسابات تطبيق مبيعات المحل                          التاريخ: ____/____/______

بريد المحل (Gmail):        ______________________   كلمة المرور: ____________
Supabase:                   (يدخل ببريد المحل)       كلمة المرور: ____________
  كلمة مرور قاعدة البيانات:                                       ____________
GitHub:                     اسم المستخدم: __________ كلمة المرور: ____________

رابط العامل:  https://______________.github.io/sales/
رابط المالك:  https://______________.github.io/sales/owner/

كلمة مرور المالك في التطبيق:  ____________
كلمة مرور العامل في التطبيق:  ____________ (تتغير من الإعدادات)

نسيت كلمة مرور المالك؟ دليل الإعداد، الخطوة ١٤.
```

### قائمة التسليم

- [ ] نموذج القرارات (القسم ٢) موقّع
- [ ] ورقة الحسابات معبّأة ومسلّمة
- [ ] الدليلان مطبوعان: المالك والعامل
- [ ] اختبار القبول مؤشَّر عليه كاملاً وموقّع
- [ ] التطبيقان مثبّتان وشغّالين على الجوالين
- [ ] النبضة شغّالة: Actions ← `keep-supabase-awake` آخر تشغيل ✅
- [ ] بيانات التجربة ممسوحة

### خروجك (بعد فترة الضمان اللي تتفقون عليها)

- [ ] **GitHub:** المستودع → Settings → Collaborators → شيل حسابك.
- [ ] **Supabase:** Organization → Team → شيل إيميلك.
- [ ] امسح من جهازك أي ملف فيه كلمات مرور أو مفاتيح العميل.
- [ ] لو صدف وعرفت أي كلمة مرور (مثلاً المؤقتة في الخطوة ٣)، اطلب من العميل
      يغيّرها: كلمة المالك من الإعدادات ← كلمة مرورك أنت.
- [ ] نسخة المشروع عندك (المجلد هذا) تقدر تحتفظ فيها، بس بدون أي أسرار.

## ١٠. بعد التسليم — متى يتصل فيك العميل؟

| يشوف | السبب | الحل |
|---|---|---|
| «نموذج القراءة متوقف» على كل الأيام | جوجل أوقفت النموذج | سر `GEMINI_MODEL` جديد (دقيقة) |
| «مفتاح خدمة القراءة غير صالح» | المفتاح انحذف أو انتهى | مفتاح جديد في `GEMINI_API_KEY` |
| «ما قدرنا نحمّل البيانات» مستمر | المشروع توقف | Supabase → Restore، وتأكد إن النبضة شغّالة |
| مساحة الصور فوق ٨٠٠ ميجا | سنين صور | تنظيف أو ترقية (الإعدادات تعرض المساحة) |
| نسي كلمة مروره | — | دليل الإعداد، الخطوة ١٤ |

**كل شهر (العميل بنفسه):** تصدير Excel للشهر اللي فات، وحفظه في مكان آمن.
